# Resource: signalfx_observability_directory

Terraform owns the complete ordered Template membership list for the Directory. Give `templates` Template IDs; their order controls their order in the UI. A membership update replaces the backend's entire list; it is not an atomic add or remove operation. The Directory API provides no ETag or other stale-write precondition, so concurrent UI, API, or Terraform changes are last-write-wins and can be lost.

Use a writable path under your own `~users/<email>/...` namespace, or under `~organization/<group>/...` with the required group permissions. Other roots may be read-only. The default is an empty membership list and `pinned = true`, so a path with no Templates remains occupied. An unpinned Directory without Templates remains occupied while it has child directories. Terraform cannot create an unpinned Directory with no Templates or children; on update, it checks for children before allowing that configuration.

After manually importing an existing Directory, add every membership that Terraform should retain to `templates` before applying; otherwise, the next apply removes them. Generated import configuration includes the memberships observed during import. Creation refuses occupied paths; import them to manage an existing entry. The API does not distinguish an unoccupied path from a stored empty, unpinned entry. An empty path normally returns an entry, so the provider reports HTTP 404 responses as API errors rather than treating them as deleted directories.

Destroying the Directory removes its membership links but does not delete the referenced Template records. Deletion is refused when the path has child directories or is an identity, canonical, or reserved service-managed entry.

## Example

```terraform
terraform {
  required_providers {
    signalfx = {
      source = "splunk-terraform/signalfx"
    }
  }
}

variable "user_email" {
  type        = string
  description = "Email address of the user whose Directory namespace is managed."
}

resource "signalfx_observability_template" "chart" {
  title        = "Request rate"
  root_element = "Chart"

  spec = jsonencode({
    "<Chart>" = [{
      "<o11y:SingleValue>" = []
      chart                = {}
      datasource = {
        program = "A = data('requests.count').sum().publish('A')"
      }
      widget = {
        title = "Request rate"
      }
    }]
  })
}

resource "signalfx_observability_directory" "charts" {
  path   = "~users/${var.user_email}/charts"
  pinned = true
  templates = [
    signalfx_observability_template.chart.id,
  ]
}
```

## Schema

### Required

- `path` (String) Decoded logical Directory path.

### Optional

- `pinned` (Boolean) Whether the Directory entry is pinned. Defaults to true so an empty Directory remains occupied.
- `templates` (List of String) Complete ordered list of Template IDs assigned to this Directory. Updating this attribute replaces the entire backend list; concurrent UI or API changes are last-write-wins.

### Read-Only

- `id` (String) The unique identifier for the resource.
